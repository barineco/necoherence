# データモデル宣言

データモデル宣言は、入力された JSON の値を型の付いた値として解釈する規則を定める、バージョン付きの定義データです。

## 宣言する内容

- 整数の値域: 名前付きの整数の範囲と、その表記 ( `integerDomains` )
- 数値: 小数を許すかどうか ( `numbers` )
- 文字列の書式: 名前付きの書式の規則 ( `formatBindings` )
- 書記素の規則: 文字列の長さを書記素 ( grapheme ) で数えるための Unicode の書記素データ ( `graphemeRules` )
- バイト列: Base64 の文字集合とパディングの規則 ( `bytesPolicy` )
- ラッパー: バイト列や文字列を包む JSON オブジェクトのキー ( `wrappers` )
- 型タグ: JSON オブジェクトの型を示すキーと、シールド形式 ( sealed form ) の設定 ( `tag` )
- 参照と出典: 宣言の識別子、リビジョン、内容のダイジェスト ( `reference` ) と、出典 ( `sourceRefs` )

## 用途

- 型宣言: 整数の値域、文字列の書式、ラッパーを、データモデル宣言の中の名前で参照する
- 値の検証: 宣言された範囲、書式、書記素の数と照らし合わせる
- エンコードとデコード: ラッパーと型タグに従って JSON を読み書きする

## 照合

型宣言のデコードと生成ライブラリの検証には、照合済みのデータモデル宣言を渡します。照合処理では、期待するデータモデル宣言の参照識別子、出典情報、および信頼できるバイト列を、入力バイト列とは別個に用意して突き合わせます。入力バイト列が信頼できるバイト列と一致し、デコードした宣言内の参照および出典が期待値と一致した時点で照合が成立します。

照合をデコード関数内で完結する言語と、呼び出し元であらかじめ照合を済ませてからデコードする言語があります。各言語における呼び出し手順やエラー型については、該当する言語ディレクトリの README を参照してください。

## データモデルの選択

適用するデータモデル宣言は呼び出し元で任意に指定できます。標準的な具体例として、プロトコル標準の AT Protocol のデータモデル宣言がプリセットとして同梱されています。全 6 言語の実装で、同じデータモデル宣言のファイルを読み込みます。

- [verification/presets/atproto-data-model/profile.json](../verification/presets/atproto-data-model/profile.json): データモデル宣言
- [verification/presets/manifest.json](../verification/presets/manifest.json): 識別子、バージョン、出典、および SHA-256 のハッシュ値
