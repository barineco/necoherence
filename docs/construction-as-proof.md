# 構成と証明

[Necoherence の概要](../README.md)

この文書では、Necoherence の実行結果を構成的証明として解釈する方法と、根拠となる Lean 4 の形式検証定理を説明します。

## 構成を証明として解釈する

実行基盤である Necoherence の操作は、入力に対して結果または明示的な失敗を返す決定的な純粋関数です。ファイルシステムや HTTP 通信への作用はリビジョンを伴う観測値および指示として、現在時刻は観測値として、いずれも明示的な入力データに含まれます。反復処理には上限回数が、ソルバーおよび合成探索には束縛数と探索ステップ数の上限が設けられているため、任意の入力に対して有限ステップで結果が返されます。ソルバーが返す証拠 ( witness ) は、検証関数による検査を通過させてから使用します。検証済みインスタンスを構築できるのは正規の検証関数のみであり、証拠データが数学的条件を満たす場合にのみインスタンスが返されます。

たとえば Rust 実装でこの設計パターンに従う型と関数は次のとおりです。

- `CheckedReachability`: 非公開フィールドのみを持つ検証済みデータ型
- `verify_reachability_witness`: この検証済みインスタンスを構築する検証関数

検証済みインスタンスが存在すること自体が、検証関数が正常終了したことの証明です。

構成的論理 ( 直観主義論理 ) においては「命題の証拠を構成するアルゴリズム」そのものが命題の証明であるため、検証済みインスタンスは検証された命題の形式的証明として解釈できます。

| 論理命題 | Necoherence における対応 |
| --- | --- |
| 命題 $P$ が成り立つ | 命題 $P$ を表す検証済みインスタンスを構成できる |
| $P \implies Q$ | $P$ の証拠から $Q$ の証拠を構成する関数が存在する |
| $\exists x.\ P(x)$ | 具体的な証拠値 $x$ と、$x$ を受理した検証済みインスタンスが存在する |
| $\neg P$ ( $P$ が成り立たない ) | 到達可能なすべての状態を網羅した閉包が存在し、その閉包内の全状態で $P$ が不成立であることが検証されている |

否定の命題も、成立する具体的な事実に基づいて構成します。例えば「目標状態に到達不能である」ことを証明するには、初期状態から到達可能なすべてのマーキングを網羅した有限の閉包を構成し、その閉包内においては目標を満たす状態が一切存在しないことを検証します。

各検証済みインスタンスの意味論を保証する定理は、[Lean の定義と定理](lean.md) を参照してください。

## 具体例

型付き遷移モデルを探索し、得られた証拠データを検証する例を示します。

モデル定義と目標:

- 場所 `ready`: 初期状態でタスクが存在する場所
- 場所 `done`: 遷移 `run` によってタスクが移動する先の場所
- 目標 1: `done` にタスクが 1 件以上存在する
- 目標 2: `done` にタスクが 2 件以上存在する

サンプルコードのソースファイルは [`solver/composition/rust/examples/reachability_witness.rs`](../solver/composition/rust/examples/reachability_witness.rs) です。

ディレクトリ `solver/composition/rust` で次のコマンドを実行します。

```bash
cargo run --example reachability_witness
```

出力結果例:

```text
reachable by ["run"]
unreachable; closure of 2 markings
```

1 行目では、ソルバーが返した遷移経路が検証 `verify_reachability_witness` に合格しています。定理 `resourceWitnessSound` により、この経路が実際に実行可能であり、最終マーキングで目標 1 が成立することが数学的に保証されます。

2 行目では、2 つのマーキングからなる閉包が返され、検証 `verify_closure_witness` に合格しています。定理 `resourceClosureSound` および検証結果により、目標 2 に至る実行経路が存在しないことが証明されます。

## 保証の適用範囲

上記の定理は、Lean 4 の仕様定義と検証関数が返す検証済みインスタンスの性質を直接証明します。他の 5 言語の実装は、同一入力に対する実行結果を Lean 4 実装の出力と突き合わせて検証しています。探索ステップ数が上限に達した場合、ソルバーは `Unknown` を返します。数学的証明として解釈できるのは、検証関数を通過した到達可能性および到達不能性の証拠に限られます。
