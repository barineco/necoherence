# 用語索引

本書では、Necoherence で使用する主要な用語を説明します。

## リソースと操作

### リソースとリビジョン

状態は、リソースごとに値とリビジョン ( 更新番号 ) の組で記録し、更新は観測されたリビジョンを前提に行います。

### 操作

入力と結果の型を指定して宣言する処理です。入力に対して結果または明示的な失敗を返します。

### ネットワーク副作用

ネットワーク副作用とは、HTTP リクエストの試行、実行ホストでの観測、再試行の制御から成る一連の作用です。各言語のコアパッケージで作用が記録され、呼び出し元から渡されたポート経由で観測結果を受け取ります。

## データモデル宣言

### データモデル宣言

書式規則、値の範囲、Unicode 書記素データ、JSON オブジェクトの分類規則などを記録した、バージョン付きの定義データです。詳細は [data-model.md](data-model.md) を参照してください。

### 転送形式

値の検証、エンコードとデコード、および実行時にデータをやり取りするためのデータ形式です。照合済みのデータモデル宣言によって定まります。

## 判定

### 値の検証

データモデル宣言のもとで宣言集合の型を解釈し、型宣言のグラフを構成します。値の検証では、このグラフに対して JSON の値が指定した型に属するかを判定します。生成コードのコーデックが値を受け取る際と、合成の実行で引数と結果を検証する際に、この処理を使います。なお、値の構造を評価する前段階として、型の解釈に必要な定義がデータモデル宣言に揃っているかを検査します。

### 確定、残余、停止、失敗

値の検証結果の分類です。確定、残余、停止は [neco-quotient](https://github.com/barineco/neco-quotient) の精密化の判定の状態 ( `RefinementOutcome` ) の三つの場合であり、これに加えて necoherence では「失敗」を別の分類として定めています。合成の未解決の理由の分類も同じ形です。

- 確定: 値が型の定義および制約条件を完全に満たしている
- 残余: 追加の型定義やデータモデル宣言が補われれば判定可能となる条件が残されている
- 停止: 所属判定に伴うステップ数や探索の深さが設定された上限に達した
- 失敗: 値が型制約に違反しているか、型宣言・データモデル宣言・証明書のいずれかに不整合が存在する

検証において未解決の条件が残る場合、その要因が入力の来歴および残余集合と関連付けられた診断値として返されます。単一の評価で異なる分類に属する複数の理由が検出された場合は、失敗、停止、残余の順に優先して分類します。未解決理由が空のまま不成立となった場合は、入力の来歴を記録した「失敗」として分類されます。

### リビジョン付きの型宣言のグラフ

型宣言グラフと、評価時点を識別する `revision` の組です。型宣言グラフは、データモデル宣言および宣言された型から構成されます。

### 精密化

精密化とは、追加の型宣言とデータモデル宣言を受け取り、既存の宣言と確定済みの判定結果を維持したまま、新しい `revision` を持つ型宣言グラフを構成する処理です。この処理は Rust で実装しています。

- 型と関数: [Rust 実装の README](../packages/rust/adapter/README.md#精密化)
- 残余と精密化の概念: [neco-quotient](https://github.com/barineco/neco-quotient)

## コード生成

### 宣言集合

型、定義、注釈を宣言した、形式 `ncoh-type-signatures@1` のデータ構造です。通信形式 `ncoh-checked-generation@5` の JSON では `signatures` に記述します。

構成要素:

- `nodes`: 宣言された型ノード
- `definitions`: 値、シンボル、メッセージ、操作 ( 操作には入力型と結果型 ( outcome ) を定義 )
- `annotations`: 宣言集合全体、グループ、定義、型、結果のいずれかに付与されるメタデータ

## 合成

### 合成問題

合成の探索の入力です。関数のシグネチャと初期入力、目標、探索の上限などを宣言します。

- 型: `CompositionInput`
- `ncoh-checked-generation@5` のフィールド: `composition.problem`
- 照合して準備した値: `PreparedCompositionInput` ( 検証と実行に使う )

### 合成

合成問題に対して、宣言された関数の呼び出しを組み合わせた結果です。計画、計画が合成問題を満たすことの証拠、選択根拠から成ります。詳細は [composition.md](composition.md) を参照してください。

- 型: `RawComposition` ( Lean は基本のパッケージの `Necoherence.SemanticComposition` に、Rust は合成のソルバーにある )
- `ncoh-checked-generation@5` のフィールド: `composition.derivation` ( 導出木 )
- 検証を通過した合成: `CheckedComposition` ( Lean では実行の関数に渡す。他の 5 言語の実行関数は、受け入れ検証の結果から得た合成を受け取る。詳細は [composition.md](composition.md#合成の実行) を参照 )

### 計画

合成のうち、呼び出す関数と引数の束縛を、呼び出しの結果やガードの分岐ごとに並べた木 ( `CompositionPlan` ) です。
