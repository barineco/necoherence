# 型付きの遷移モデル

状態遷移モデルは、場所 ( プレース ) と遷移 ( トランジション ) とトークンから構成されます。ソルバーで探索し、判定結果とその証拠 ( witness ) を返します。

- マーキング: 各場所におけるトークンの配置。モデル全体の現在の状態を表す
- 閉包: 初期状態から到達可能な全マーキングの集合
- 証拠 ( witness ): ソルバーが探索結果とともに返す証明データ。到達経路、閉包、デッドロック状態のマーキング、循環経路のいずれか

## 実装

モデルの定義は、各言語の MIT License の実装にあります。

- Lean: `Necoherence.TypedMapping`
- Rust: `necoherence::typed_mapping`
- Gleam: `necoherence/typed_mapping` ( モデルの型と、目標の評価、一段階の遷移、経路の再生の関数を持つ )

ソルバーが返した証拠 ( 到達、閉包、非循環 ) は、Lean、Rust、Gleam の実装にある検証の関数が、これらの定義に基づいて検証します。ソルバーの実装は [solver/](../solver/) 配下にあり、Rust と Lean で提供しています。

## ソルバーの入力

入力データ ( `SolverInput` ) は、次の要素で構成されます。

- 場所、遷移、および入力束縛の定義
- 探索目標、宣言グラフ、初期マーキング ( 各場所の初期トークン配置 )
- 探索上限値 ( `max_bindings` および `max_search_steps` )

## 操作と結果

ソルバーの検証操作は、到達可能性判定、デッドロック検出、整礎性判定です。任意の入力に対して、下表のいずれかの結果を返します。表中の結果名は Rust 実装のものであり、Lean および Gleam 実装にも各言語の命名規則に合わせた同等の型を定義しています。

| 操作 | 結果 | 意味 |
| --- | --- | --- |
| 到達可能性 | `Reachable` | 目標に到達可能。証拠として遷移経路と最終マーキングを返す |
| 到達可能性 | `Unreachable` | 到達可能なすべての状態を探索したが目標に到達不能。証拠として閉包を返す |
| デッドロック | `Deadlocked` | 目標未到達かつ発火可能な遷移が存在しないマーキングを検出。証拠として該当マーキングを返す |
| デッドロック | `NotDeadlocked` | デッドロックなし。発火可能な遷移の一覧を結果に含む |
| 整礎性 | `WellFounded` | 探索した閉包が非循環 ( 有限停止 ) である。証拠として閉包を返す |
| 整礎性 | `NotWellFounded` | マーキングの循環を検出。証拠として循環経路を返す |
| 共通 | `Invalid` | 宣言または入力が不正。エラー理由を結果に含む |
| 共通 | `Unknown` | 束縛上限または探索ステップ上限に達し、探索が打ち切られた |

呼び出し元の前提違反が起きた場合、Rust と Gleam の実装では `SolverFailure` として返されるのに対し、Lean の実装では上表の結果値のみを返します。
