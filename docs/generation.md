# コード生成

コード生成ツールは、型と操作の宣言から、各言語の型定義とコーデックを生成します。識別値 `basis` の計算と受け入れ検証の関数は各言語の README を、ツールの実行方法は [generator の README](../generator/README.md) を参照してください。

## 入力

入力は、生成に使う宣言と、その宣言の内容を識別する値をまとめた JSON です。形式は `ncoh-checked-generation@5` で、スキーマ定義は [ncoh-checked-generation-v5.schema.json](../verification/declaration/ncoh-checked-generation-v5.schema.json) を参照してください。

- `schema`: 形式名 ( 文字列 `ncoh-checked-generation@5` )
- `basis`: 宣言の内容を識別する値
- `signatures`: フォーマット `ncoh-type-signatures@1` の [宣言集合](terminology.md#宣言集合)
- `composition`: `null`、または合成問題とその導出木
- `entrypoints`: 公開対象とするエントリポイント定義の一覧

生成の識別値 `basis` は、宣言の中身から決定的に計算されます。受け入れ検証時には、この値を宣言の中身から計算し直した値と、呼び出し元が別の経路で得た期待値の両方と照合し、生成結果が意図した宣言内容から作られたことを検査します。

入力の `composition` に導出木を含める場合、受け入れ検証が復号した計画がコード生成の出力に組み込まれます。ここでは、Rust のコード生成ツールは計画を復号するのみにとどまり、導出木が合成問題の解であることの検証は合成のソルバーが行います。合成問題と導出木の詳細は [合成](composition.md) を参照してください。各 `entrypoints` 項目には、公開識別子と対応する定義 ID が含まれます。

## 出力

出力は、対象言語で記述された単一ファイルのソースコードです。依存先は、該当言語の MIT License の実装のみです。出力ファイルの先頭には、対象言語のコメント形式で著作権、ライセンス、生成元を掲載しています。この表示を残す限り、生成したコードを利用者のプロジェクトのライセンスのもとで改変し、再配布し、別の用途に利用できます。

- 著作権: `SPDX-FileCopyrightText: 2026 barineco`
- ライセンス: `SPDX-License-Identifier: MIT`
- 生成元: `Generated by Necoherence <バージョン> (https://github.com/barineco/necoherence)`

出力コードの内容:

- 宣言された値の型定義とコーデック
- 各操作の引数型および結果型
- 宣言された注釈 ( アノテーション )
- 合成結果を実行するコード ( `composition` が指定されている場合 )

### 合成結果の実行

生成コードは合成の呼び出し用関数を持ち、合成の実行は基本パッケージ ( コアランタイム ) で行います。

生成コードの構成:

- 合成問題と導出木を、各言語のネイティブなデータ構造として構築するコード
- 関数ごとの型付きの実装の定義と、初期入力および結果の型
- 埋め込んだ値を渡して、基本パッケージの受け入れ検証の関数と、実行の開始および再開の関数を呼び出す公開関数

導出木は合成のソルバーが作り、ソルバーは作った合成を自身の検証関数で確かめます。これに対して、Lean の定義は導出木を検証し、Rust のコード生成ツールは受け入れ検証 ( JSON の形式、`basis` の照合、宣言の検査、計画の復号 ) を行います。

基本パッケージの構成:

- 合成入力の準備と、受け入れ検証
- 計画に沿った関数の実装の呼び出し、リソースの束縛、および状態の記録と更新

関数の実装に渡される引数は、値のポートだけです。

生成された Lean コードが公開する関数:

- `run`: 埋め込んだ値から合成入力を準備し、合成を検証してから実行を開始する
- `resume`: 実行を再開する。実行時エラーとして、コアパッケージの `RunFailure` を返す

呼び出し元から渡された HTTP 用の実装が事前完了を返した場合、その結果が「操作宣言で定義済みの外部条件エラー」であり、かつ「返された結果識別子がそのエラー定義と一致する」場合にのみ受理されます。それ以外の事前完了は、実行時エラー `invalidPlan "undeclared external completion"` として拒否されます。

コードの構成や呼び出し手順の詳細は、[コード生成ツールの説明](../generator/README.md) を参照してください。

## 失敗

入力の JSON の形式が不正な場合、`basis` の照合が失敗した場合、あるいは宣言の検査や計画の復号で拒否された場合はエラーを返します。エラーの型や処理方法は言語ごとに異なり、詳細は [generator の README](../generator/README.md) に記載しています。

### 受け入れ検証

コード生成の前には、受け入れ検証 ( admission ) を行います。次の一覧は Lean の `AdmissionFailure` の一覧です。このうち Rust のコード生成ツールの受け入れ検証が返すのは、項目 1 から 9 です。

1. `unsupportedSchema`: スキーマ識別子がサポート対象外
2. `entrypointsEmpty`: エントリポイントが空かつ合成問題が `null`
3. `entrypointIdentityEmpty`: エントリポイント識別子が空
4. `entrypointDuplicate`: エントリポイント識別子の重複
5. `entrypointUnresolved`: エントリポイントが参照する定義が宣言集合内に存在しない
6. `library`: 宣言集合が型・操作の宣言規則に違反している
7. `certificate`: `basis` が、中身から計算し直した値、または呼び出し元の期待値と一致しない
8. `wire`: 合成問題または導出木の JSON フォーマットが不正
9. `compositionInput`: 合成入力の準備処理に失敗
10. `composition`: 導出木の検証処理に失敗 ( Lean の導出木を検証する受け入れ検証と、合成のソルバーの検証が返す )

項目 9 および 10 のエラーには、合成入力の準備処理および導出木の検証処理が返した元の詳細エラーが含まれます。

生成識別値 `basis` の `problem_sha256` は、合成問題と導出木の両方を含む JSON のダイジェスト値です。そのため、導出木部分のみを変更した JSON は `certificate` によって拒否されます。観測関数族のダイジェスト値は、合成の `goal` から作る観測関数族の JSON から計算し、合成を含む入力だけがこの値を持ちます。観測関数族には次の要素が含まれます。

- 成功時の出力の識別子と型制約
- 失敗時の埋め込みの識別子、型制約、および終了時のリソース要件
- 終了時のリソース要件
- 中断 ( `pending` ) とネットワーク指示 ( `network_instruction` ) の列
- 残余 ( residual ) の集合
- 型付きの実行失敗の種類
- 証明書の来歴

照合の期待値が持つ二つのフィールドは次のとおりです。

- `basis`: 期待する識別値
- `observations`: 期待する観測関数族

入力の `goal` から作った観測関数族が期待する観測関数族と一致する時に、照合は観測の条件を満たします。生成されたコードは、この期待値を埋め込み、初期化の時に一度だけ照合します。
